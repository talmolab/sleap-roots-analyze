## Why

The `SUMMARY.md` generated by `sleap-roots-analyze run-all` shows results (samples, traits, heritability) but does not display the configuration parameters used for each pipeline. Users cannot quickly compare settings across datasets without opening individual config files.

For example, a user running 4 QC pipelines cannot see at a glance that:
- turface_150genotypes uses H² threshold 0.40
- turface_19genotypes uses H² threshold 0.60
- cylinder_edpie uses H² threshold 0.60
- root_core uses H² threshold 0.50

This makes it difficult to understand why results differ across datasets and to document analysis choices for publication.

## What Changes

**ADDED** a "## Configuration Comparison" section to `SUMMARY.md` containing comprehensive tables showing ALL config parameters across pipelines:

1. **QC Configuration Tables** - One table per config section, ALL parameters included:
   - `cleanup` section: max_nan_fraction, max_zeros_per_trait, max_nans_per_trait, min_samples_per_trait
   - `outlier_detection` section: traditional_methods, clustering_methods, mahalanobis.variance_threshold, mahalanobis.use_chi_squared, mahalanobis.chi2_percentile
   - `outlier_removal` section: strategy, method
   - `heritability` section: enabled, threshold, generate_diagnostics
   - `pca` section: n_components, feature_selection_strategy
   - `visualization` section: dpi, figsize, title_fontsize, label_fontsize, tick_fontsize, legend_fontsize, figure_format, enable_batched_plots, batched_plot_threshold, batch_size
   - `adaptive_sizing` section: enabled, base_width, base_height, width_per_item, height_per_item, min_width, max_width, min_height, max_height
   - `root_core` section (if present): core_qc.enabled, core_qc.max_missing_proportion, core_qc.remove_outliers, core_qc.detect_value_outliers, core_qc.max_deviation_from_median, aggregation_method, generate_depth_profiles

2. **Visualization Configuration Tables** - ALL viz pipeline parameters

3. **Cross-Platform Configuration Tables** - ALL cross-platform parameters

The tables use datasets as columns for easy side-by-side comparison. Parameters with identical values across all configs are marked with "✓ (same)" to highlight where configs differ.

**MODIFIED** `PipelineRunner._generate_summary()` to:
- Read each config file used in the run
- Extract ALL parameters from each config section
- Format as markdown tables with datasets as columns
- Highlight parameters that differ across configs

## Impact

### Affected Specs

- `pipeline-runner-skill` - Adding new summary section requirement

### Affected Code

- `src/sleap_roots_analyze/pipeline_runner.py`:
  - `_generate_summary()` - Add config comparison section
  - New: `_format_config_comparison()` - Generate config comparison tables
  - New: `_extract_all_config_params()` - Extract ALL parameters from config file
  - New: `_flatten_config_dict()` - Flatten nested config dict to dot-notation keys
  - New: `_format_comparison_table()` - Format parameters as markdown table
