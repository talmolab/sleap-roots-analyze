## Why

Trait boxplot figures become unreadable when genotype count exceeds ~8 or genotype IDs
are long strings. Three compounding issues cause this:

1. **Layout timing**: `tight_layout()` runs inside `create_trait_boxplots_by_genotype()`
   before `suptitle()` is added by the batched wrapper, causing the title to overlap the
   top row of subplots.
2. **High horizontal threshold**: The default `horizontal_threshold=15` means vertical
   boxplots are used even with 14 genotypes, where rotated x-labels overlap severely.
3. **Fixed subplot size**: `subplot_size=(4.0, 4.0)` doesn't scale with genotype count
   for vertical orientation, so subplots are cramped regardless of how many categories
   exist.

These issues affect EDA and publication figures generated by `ExploratoryAnalysisStep`
and `GenerateStaticFiguresStep`.

GitHub Issue: #73

## What Changes

- **Fix layout timing**: Remove `tight_layout()` from `create_trait_boxplots_by_genotype()`
  and let the batched wrapper (or caller) handle layout after adding suptitle. Use
  `fig.tight_layout(rect=[0, 0, 1, 0.96])` in the batched wrapper after suptitle.
- **Lower horizontal threshold**: Change default `horizontal_threshold` from 15 to 8
  in both `create_trait_boxplots_by_genotype()` and
  `create_trait_boxplots_by_genotype_batched()`
- **Adaptive subplot width**: For vertical orientation, scale subplot width with genotype
  count: `subplot_width = max(4.0, n_genotypes * 0.5)` to ensure labels have room
- **Label font scaling**: Reduce x-axis tick label font size when genotype count is high
  (e.g., fontsize=max(6, 10 - n_genotypes * 0.3))

## Impact

- Affected specs: `visualization-pipeline` (boxplot readability requirements)
- Affected code:
  - `src/sleap_roots_analyze/visualization.py` (primary fix)
  - `tests/test_visualization.py` (new tests)
- No breaking changes to public API (parameter defaults change, but existing explicit
  values still work)
- Visual output changes for datasets with >8 genotypes (improvement)
